# Metric families

Prioritize metrics that change how a reviewer understands technical difficulty, scope, or outcome:

- **Scale:** requests per second, events per day, users, tenants, devices, services, repositories, regions, or data volume.
- **Performance:** p50/p95/p99 latency, throughput, CPU, memory, startup, build, or query time.
- **Reliability:** availability, SLO, error rate, incidents, MTTR, recovery time, or page rate.
- **Cost and efficiency:** cloud spend, compute, storage, utilization, engineering hours, or toil.
- **Delivery:** lead time, migration duration, deployment frequency, or release cadence.
- **Product and business:** adoption, conversion, retention, customers, revenue influenced, or activation.
- **Developer productivity:** CI duration, setup time, test throughput, onboarding, or developer hours.
- **Quality and security:** defect rate, rollback rate, vulnerabilities, exposure, response time, or false positives.
- **Organizational scope:** teams, engineers, services, migrations, standards, or regions influenced.
- **ML and data:** precision, recall, latency, inference cost, training time, quality, or data volume.

Ask the smallest answerable question. Prefer a before/after, range, count, rate, or operational boundary the candidate can recover. Accept honest approximations only when the user labels them as approximate.
